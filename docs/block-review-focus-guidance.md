# Block-review evidence and focus guidance

The subsequent [focus-identity fix](block-review-focus-identity.md) replaces repeated
sport/capability fields in model output with server-provided IDs. Resolved persisted
guidance retains full metadata. Evidence and coaching semantics below are unchanged.

September 7, 2026 follow-up to the first live `successful-run-block` review. This refines evidence naming and selective progression without changing block architecture, enabling production live reviews, or making paid calls.

## Audit findings

| Area | State before this refinement |
| --- | --- |
| Review context | Active block/week/focus projection, objective/goals, effective week/future pattern, captured workout/activity/feedback evidence, restrictions, adjustments, availability, races, recent history, and an internal freshness fingerprint |
| Proposal | Only `decision` and a short `rationale`; no per-focus instruction |
| Persistence | Append-only `DevelopmentBlockReview` JSON with request/response, optional evidence/source, dates and revision; block revision/status updated atomically |
| Rationale | Supplied by the simulated provider or generated by the live reviewer; deterministic code did not construct an evidence-derived rationale |
| `actualMinutes` | Production summed owned **unlinked database activities** for the reviewed local week. It did not copy planned minutes. However, the synthetic fixture created activity rows using exactly the planned durations, which made the categories look equivalent. |
| Planned/reported duration | Planned minutes summed all prescribed workouts. Reported completed-session counts used stored completion states, but there was no separate completed-prescription minute total. |
| Workout links | No workout-to-activity relation exists in the database or workout states. Performance evidence may reference an activity, but that is not a workout link. |
| Linked duration | Absent from the review context. Existing activity summaries contained minutes/distance, but no prescribed workout identity. |
| Link coverage | `activityLinkingAvailable: false`; interval execution was `achievedTargets: null`. |
| Weekly handoff | `developmentBlock.previousReview` carried the latest applicable request/concise response; detailed evidence was omitted. |
| Smallest change | Version the evidence JSON, add focus guidance to review request JSON, and reuse the existing weekly handoff, provider, persistence, and concurrency checks. No new table or job type. |

The original fixture comments also explicitly said “expected effort and recovery.” Thus the live rationale did have an athlete-report source for that wording, but presented it too strongly. The default successful fixture now supplies no recovery claim, and the prompt requires attribution when an explicit recovery comment is present. Neither absence of adverse feedback nor ordinary RPE establishes measured recovery.

## Evidence version 2

| Sport field | Meaning |
| --- | --- |
| `plannedMinutes`, `plannedSessions`, `plannedLongestMinutes` | Prescribed training, or null when no saved plan exists |
| `reportedCompletedPlannedMinutes` | Sum of **prescribed** durations for workouts explicitly marked `COMPLETED`; modified/stopped/unreported sessions do not contribute |
| `reportedCompletedSessions` | Count of workouts marked completed |
| `recordedActivityMinutes`, `recordedActivitySessions`, `recordedLongestMinutes` | Activity-record values **only for explicitly linked workouts**; null when no linked records exist |
| `activityCoverage.linkedWorkouts` | Distinct prescribed workouts with a linked record |
| `activityCoverage.plannedWorkouts` | Number of prescribed workouts, including ones not reported completed |
| `unlinkedActivityMinutes`, `unlinkedActivitySessions` | Separately labeled background activity for the local week; not verification of prescribed workout execution |

With two completed 60-minute run prescriptions and no links, reported-completed planned minutes are 120, recorded workout minutes are unknown, and coverage is 0/2. With one explicitly linked 58-minute run, recorded minutes are 58 and coverage is 1/2. With a second linked 60-minute run, recorded minutes are 118 and coverage is 2/2, while reported-completed planned minutes remain 120.

`recordedActivitySessions` counts activity records; `linkedWorkouts` counts distinct workout identities. Multiple records linked to one workout contribute their recorded durations but do not increase workout coverage. Recorded longest refers to the longest individual activity record. Unknown execution is not zero execution.

Activity evidence now accepts an explicit nullable `workoutId`. Links must refer to a prescribed workout of the same sport; duplicate activity/workout identities and incorrect calculated totals are rejected. Production continues to emit null identities and `activityLinkingAvailable: false`, because no link-storage system exists. Partial/full linked fixtures exercise the contract and calculations without adding matching, UI, or a database migration.

Linked activity summaries support recorded duration/distance evidence. They still do not establish exact power/pace execution, time in target, pauses, interval success, measured recovery, or fitness improvement. Raw streams and detailed execution analysis remain deferred. `achievedTargets` remains null. All records must belong to the reviewed local week; ownership/date filtering and snapshot freshness remain database responsibilities.

## Two independent decision levels

The block-level decision retains its six existing values and controls lifecycle/future week roles. The structured reviewer output now also requires exactly one entry for every existing sport/capability:

```json
{
  "decision": "PROGRESS",
  "focusGuidance": [
    { "sport": "RUN", "capability": "LONG_ENDURANCE", "action": "PROGRESS", "rationale": "Reported primary execution supports a small progression." },
    { "sport": "BIKE", "capability": "THRESHOLD", "action": "HOLD", "rationale": "Preserve useful secondary work while prioritizing the run stimulus." },
    { "sport": "SWIM", "capability": "SUSTAINED_ENDURANCE", "action": "MAINTAIN", "rationale": "Continue sufficient maintenance exposure." }
  ],
  "rationale": "Reported completion supports continuing the block with targeted progression; recorded execution remains uncertain."
}
```

`FocusAction` is `PROGRESS | HOLD | MAINTAIN`. Rationales are concise (up to 600 characters per focus); no exact workout duration, calculated metric, new focus, or progression-strategy change belongs in the proposal. The examples are illustrative, not hardcoded model responses.

Deterministic validation requires complete, unique focus identity coverage. Global PROGRESS needs at least one focus PROGRESS. A maintenance focus must MAINTAIN; reprioritizing it requires changing the block strategy. Development focuses use PROGRESS or HOLD. Recovery and terminal decisions cannot authorize focus progression. Global HOLD normally holds development focuses; a selectively progressing focus remains possible when explicitly justified, as requested. There is no one-focus progression cap.

The prompt prioritizes the primary focus and the smallest useful set of progressions. A secondary focus can progress too when its evidence and the combined training stimulus justify it. Primary success does not establish secondary success. Maintenance should not become the week's development priority merely because it fits the schedule.

## Persistence, compatibility, and weekly handoff

Focus guidance is stored at `review.request.focusGuidance` alongside the existing global decision. New review-service snapshots use evidence version 2 and source `block-review-v2`. Their concise `response.sports` carries the same explicit sport evidence. No Prisma migration was added: the existing JSON columns and append-only revision conventions suffice.

Legacy v1 evidence, including `actualMinutes`, remains readable and unchanged in history. Those values are not converted into linked execution. Legacy/admin requests without guidance also remain readable; no historical focus actions are invented. The older administrative `review` command retains its original response representation for compatibility. Use `review-week` for the new evidence-rich path; its supplied proposal now requires guidance for every active focus.

The existing `activeBlockForWeek` projection passes only the most recent applicable review into `PlanningContext`, preserving its original guidance. Weekly OpenAI input therefore receives `developmentBlock.previousReview.request.focusGuidance`; no extra history or duplicate top-level field is needed. Revising a review appends a row, and later block changes do not recompute previous actions. The existing stale revision/evidence checks, locks, terminal gates, and protected workout behavior remain intact.

The weekly prompt treats focus action separately from progression strategy: RUN/LONG_ENDURANCE + LONG_SESSION + PROGRESS permits a small long-session change, not automatic increases in volume/frequency/intensity together. HOLD preserves similar stimulus without requiring an identical workout. MAINTAIN supplies sufficient exposure without developmental priority.

Week role remains authoritative. RECOVERY, TAPER, RETURN, and RACE semantics override normal focus progression. Global PROGRESS does not change those roles by itself. Terminal blocks cannot direct future normal generation until replacement. Legacy guidance absence is not implicit permission to progress everything. Desired weekly time goals remain goals; this change does not introduce new volume limits or numerical progression formulas.

## Reviewer prompt and evaluator changes

The reviewer explicitly distinguishes prescribed, reported, linked, and unlinked evidence; forbids unsupported claims about recovery, tolerance, or achieved targets; and attributes comments to the athlete. Missing negative evidence is not positive evidence, and missing execution evidence is not proof of failure. It may compare reported RPE with the supplied easy/quality pattern, without asserting measured recovery.

The existing OpenAI Structured Outputs schema now requires `decision`, `focusGuidance`, and `rationale`. Provider transport, model, timeout/correction handling, opt-in behavior, and production live-review restriction are unchanged. The mock SDK test verifies the new wire contract and correction behavior without a real request.

Evaluator summaries display each focus's role/action/rationale, planned minutes, reported-completed **planned** minutes, linked recorded minutes/longest/session coverage, unlinked background minutes, and `UNVERIFIED`, `PARTIAL duration coverage`, or `COMPLETE duration coverage`. Complete duration coverage is not complete target verification. Reference guidance is included for human comparison; a live schema pass is not a coaching-quality verdict.

There are now 22 review scenarios: the existing 18 plus explicit primary-and-secondary progression, primary success with secondary difficulty, partial links, and full links. `successful-run-block` has no synthetic activity rows or recovery assertion; its reference is global PROGRESS with primary run PROGRESS, secondary bike HOLD, swim MAINTAIN. Other fixtures retain explicitly unlinked activity rows to exercise background totals.
